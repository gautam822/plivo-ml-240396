Teaching a voice agent when you're actually done talking

A causal, CPU-real-time model that reads the prosody of a phone turn — pitch, energy, rhythm, voice quality — and predicts at every pause whether the speaker has finished. No pretrained models: signal processing, small tree ensembles, and a lot of honest measurement.

The problem

At every silent gap a voice agent must decide: is the human done, or just thinking? Fire early and it talks over people; fire late and calls fill with dead air. The provided silence-only baseline has no idea which pause is which (AUC 0.50) — the information is in how the last words were spoken.

What the model listens for

For each pause, 38 features are computed from audio strictly before it: pitch slope and range in semitones (speaker-relative), energy trailing off against an adaptive per-prefix speech baseline (fixed thresholds break across recording levels), final-syllable and segment-rhythm timing, voice quality (spectral tilt, six band energies, flatness, pitch confidence), and causal turn context (elapsed time, audio-detected pause history). Frame descriptors are computed once per file and sliced causally per pause — 31 ms per pause on a laptop CPU.

Three decisions beyond a stock classifier

1 — Scorer-aware weighting. A hold shorter than the agent's action delay can never cause a false cutoff, so it gets 0.1× training weight; long holds — the ones that consume the 5% interruption budget — get 3×. The classifier spends its capacity exactly where errors cost points.

2 — Per-language models. Error analysis showed the two languages end turns differently: Hindi endings fall in pitch (eot-vs-hold separation 0.45); English endings don't (0.05) — English marks completion with energy and timing. One shared model averaged these away; separate small ensembles (5 seeds each, averaged) beat it.

3 — Audio-based language routing. Routing by file naming (en__/hi__) is a trap: a hidden set named differently would fall to a combined model costing +150 ms on Hindi. A language classifier trained on the same causal features now softly blends the two ensembles whenever naming carries no hint.

On evaluation honesty. The final model scored on its own training turns reads ~250 ms / AUC 0.99 — train-on-test leakage, claimed nowhere. Every number above is out-of-fold: scored by a model that never saw that turn. And when a hyper-parameter sweep looked good on one split, we stress-tested it across five shuffled splits — every "gain" evaporated, so it was rejected (RUNLOG Run 7). On 200 turns, anything not split-robust is overfitting.

Built for production

predict.py imports no scikit-learn: trained trees ship as JSON and run in ~40 lines of numpy, so grader-side version differences cannot break inference. It survived a deliberate gauntlet — corrupt wavs, stereo input, a labels file stripped to the four causal columns, renamed files with no language hints, and execution from a different working directory. check_causality.py proves mechanically that replacing all audio after a pause with noise changes no feature. ~31 ms per pause, CPU only.
